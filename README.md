# teapot

학교의 냉방 낭비 의심 장소를 찾는 모바일 대응 웹 앱 초안입니다. 모든 사용자는 동일한 화면을 이용합니다.

## 초안에서 할 수 있는 일

- 학교 전체 12개 교실 현황과 층별 필터
- 교실별 재실 추정, 문 열림, 에어컨 가동, 전력, 온도 확인
- 지속시간에 따른 경고와 우선 확인 장소 목록
- 알림 읽음 처리(문제 해결과 별도)
- 교실 검색, 에너지 흐름 및 층별 통계
- 시연 센서를 변경하고 5분 경과 후 판단 결과 확인
- 모바일 하단 내비게이션, PWA 홈 화면 설치, 오프라인 화면

**모든 데이터는 시연용입니다.** 실시간 학교 센서, 학습된 AI, 푸시 알림, 실제 에어컨 제어, 여러 기기 간 동기화는 아직 구현하지 않았습니다. 새로고침하면 시연 변경 사항이 초기화됩니다.

## 로컬 실행

Node.js 20 이상에서 `npm run dev` 후 http://127.0.0.1:4173 을 엽니다. 외부 패키지 설치는 필요 없습니다. `npm test`는 판정 로직을, `npm run check`는 진입점·자산·문법을 검증합니다.

## 프로젝트 구성

- `dist/`: Git에 추적되는 웹 소스 및 바로 배포 가능한 정적 파일
- `dist/model.js`: 시연 데이터와 낭비 판정 로직
- `dist/app.js`: 동일 상태를 쓰는 모든 화면과 인터랙션
- `dist/manifest.webmanifest`, `dist/sw.js`: 설치·오프라인 기반
- `docs/ROADMAP.md`: 센서·AI·앱 확장 방향
- `.openai/hosting.json`: Sites 배포 대상 및 정적 디렉터리

별도 컴파일 과정이 없어서 `dist/` 자체가 소스입니다. GitHub Pages, 일반 정적 호스팅에서도 이 디렉터리를 서비스할 수 있으며 하위 경로를 지원합니다.

## 판정 원칙

1. 비어 있음 추정 + 냉방 가동 + 5분 이상 지속 → 확인 필요
2. 여기에 문 열림이 겹침 → 최우선 확인
3. 재실 여부와 무관하게 냉방 중 문 열림 지속 → 환기 목적 확인
4. 예시 기준선보다 40% 및 200W 넘게 높은 소비 지속 → 사용량 확인
5. 센서 미수신 → 확인 불가. 전력 합계에서 제외

상태 변경 후 새 조건의 지속시간은 0분부터 시작합니다. 알림을 확인해도 원인 조건은 유지됩니다. PIR 움직임 없음만으로 빈 교실을 확정하면 안 됩니다.

‘빈 교실 냉방 의심량’은 해당 시연 구간의 냉방 전력 × 시간입니다. 냉방이 모두 불필요했다고 확정할 수 없으며, 문 열림 손실량이나 검증된 절감 실적이 아닙니다. 요금과 탄소 환산은 실제 계약·근거를 확보한 후 추가합니다.

## 검증 범위

도메인 로직과 정적 파일 검사를 제공합니다. 브라우저별 설치 가능 여부, 실제 휴대폰 표시, WebMCP 지원 브라우저의 도구 실행은 별도 기기 검증 대상입니다. WebMCP는 미지원 브라우저에서도 일반 서비스에 영향을 주지 않습니다.

아이콘은 프로젝트 자체 도형이며, Google Fonts가 차단되면 기기 기본 글꼴을 사용합니다.
