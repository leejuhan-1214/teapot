# teapot 다음 단계

## 1. KOSA용 제품 정리

PC와 휴대폰에서 동일한 교실 상태·알림이 보이는 대시보드를 완성합니다. 현재 초안은 사용자 구분이 없는 공통 화면입니다. 실제 데이터를 받을 때는 역할 구분 없이 학교 단위 접근 보호를 별도로 검토합니다.

교실 두 곳의 관찰 기록을 확보해 출입, 쉬는 시간, 환기, 수업, 방과 후 상황에서 잘못된 경고가 얼마나 발생하는지 검증합니다. 현재 5분 기준은 고정된 규정이 아니라 현장 검증할 기본 설정입니다. 무인 신호, 문 열림, 가동 신호에 독립된 타이머를 두는 단계로 발전시킵니다.

## 2. KDN용 센서 연결

자석식 문 열림 센서, ESP32, 온습도센서, 실제 재실 검증에 맞는 센서, 계측 가능한 부하로 교실 2곳을 구성합니다. 시연은 저전압 LED와 팬으로 하며 팬을 에어컨 모형으로 명확히 표시합니다. INA219는 저전압 DC 계측용이지 실제 교실 에어컨 계측기가 아닙니다.

센서 → 학교 게이트웨이(MQTT) → 서버 저장·판정 → PC·모바일 화면 순서로 연결합니다. room_id, captured_at, received_at, door_open, occupancy_state, ac_running, power_w, quality를 전달하고 미수신을 정상으로 처리하지 않습니다. 에어컨 ON 명령과 실제 작동 상태를 구분합니다.

알림 판정은 앱을 닫아도 서버에서 계속 실행합니다. 확인 처리와 원인 해제를 별도 상태로 저장하고, 재발 알림도 별도 사건으로 관리합니다.

## 3. AI 적용

기상·시간표·교실 전력의 실제 데이터를 축적한 뒤 전주 동시간대 및 선형회귀 기준 모델과 LightGBM을 비교합니다. 다음날 예측에는 그 시점에 이용 가능한 기상 예보와 변수만 씁니다. 시간순 검증으로 미래 정보 누수를 막습니다.

학습된 모델의 예상 사용량과 실제 사용량 차이를 낭비 의심 신호로 사용합니다. 이상 사용과 낭비 확정은 다르며, 실측 학교 데이터로 검증하기 전 가상 데이터 정확도를 실증 성과로 표현하지 않습니다.

## 4. 앱 확장

현재: 반응형 웹 + manifest + service worker + 설치 아이콘으로 PWA 기반을 제공합니다. iPhone은 Safari 공유 메뉴의 홈 화면에 추가, Android는 Chrome의 설치 메뉴로 이용합니다. 호스팅 접근 정책과 브라우저에 따라 설치 과정이 다르므로 실제 기기로 확인합니다. 저장된 화면이 오프라인의 현재 센서값처럼 보이지 않도록 표시합니다.

다음: 공통 백엔드와 서버 알림 처리, 사용자 동의 후 Web Push를 연결합니다. iOS의 Web Push는 홈 화면에 추가된 웹 앱과 지원 OS가 필요합니다.

이후: 앱스토어 배포 또는 네이티브 기능이 필요하면 Capacitor로 기존 웹 UI를 Android/iOS 앱에 포함합니다. Android 앱 빌드와 iOS 빌드·서명·심사는 별도 단계입니다. 현재 APK/IPA를 제공하는 것은 아닙니다.

## 발표 시연

초기 문제 교실 → 상세 화면 → 알림 확인(경고 유지) → 시연 에어컨 끄기(조건 해제) → 다시 가동 → 5분 경과(재발 경고) → 센서 수신 중단(상태 불명).

현재 데이터는 브라우저 메모리에만 있으며 새로고침하면 리셋됩니다. 통계 그래프의 과거 곡선은 고정 예시이고 현재 센서 변경은 끝점과 합계에 반영됩니다.
